AbstractGym:
can an LLM execute a program?

Can a language model run a program, not just write one? The question is old. Learning to Execute (2014) trained networks to print the output of short Python programs. It matters more now. Reasoning models are trained against checkers that look only at the final answer, and agents are asked to follow procedures over many steps. Theory says that writing out intermediate steps, chain of thought, lets a transformer compute far more than in one pass (Feng et al., Li et al., Merrill and Sabharwal). But “can” is not “does”, and Turpin et al. showed that written steps do not always reflect how an answer was reached.

AbstractGym tests it directly. Each puzzle asks whether a grammar, a set of rewriting rules, can build a string: with \(S \to a\,S\,c \mid b\,S\,d \mid e\), the steps \(S \to aSc \to abSdc \to abedc\) build \(abedc\). The model is handed the exact procedure, a search that tries rules in order, cuts a branch as soon as it disagrees with the string and backtracks, and the gym grades every move against the one correct run; the first wrong move ends it. The same puzzle is also asked as a plain yes or no. Every string comes with a grammar that builds it and one that does not, so ignoring the grammar scores exactly 50%.

The main result is easy to state. Qwen3-14B decides 204 of 240 puzzles, where a coin gets 120, but executes the procedure to the end only 30 times. At its first mistake it jumps to the move whose outcome it can already see.

I started from that gap and asked six questions, each a hypothesis I tried to break.

The first was whether the model runs the procedure silently and then answers. If it did, its answers and its written work should agree. They did not: on 208 puzzles the answer was right and the written run was not, and never the other way round. Once I removed a giveaway cue from the puzzles, the answers held up only where one visible comparison settles the question, and on deep random grammars they were a coin flip.

The second was whether chain of thought is just extra room. If the model knew the algorithm and only lacked space, thinking mode should fix it. It helped a little, from 28 to 44 complete runs at about 7× the tokens, and 42 of the 44 were puzzles whose answer is yes: extra room helped it build a match, not rule every branch out.

The third was whether the problem is memory or the step. I let the gym hold the search state exactly, so the model only had to pick each next move. That should have removed bookkeeping errors, yet complete runs rose only to 40–68 of 240, and spelling out facts about the state did not help. The step itself was missing. So I tried to teach it: trained with a small adapter on single correct moves, on a simpler bracket-matching task, the model went from 43 to 60 complete runs out of 92, with results that depended on the symbols and the training seed.

The fourth was whether a model that knows every step can also carry the whole run in its own text. Trained on single moves, it completed 133 of 240 runs with the gym holding the state, but none when it had to write the run itself; it wrote one move and stopped. Adding whole written runs to the training gave 100 written and 156 with the gym's memory, the best result of the study.

The fifth was whether deciding and executing are one skill. If they were, training either should improve both. On the bracket task, training on answers raised correct answers from 62 to 82 of 92 and dropped complete executions from 43 to 11. Training on steps raised executions to 60 and left the answers unchanged. They behave like two different skills.

The sixth was whether the model's own history steers it. I handed it a written start with the first moves made wrong. If each step were decided fresh, nothing should change. Instead correct later moves fell from 502 to 214 of 576, and the model neither kept the original plan nor faithfully followed the wrong one.

For chain of thought, writing steps is probably not the same as following them. Extra room barely helped, the model's own written history steers what comes next, and grading only the final answer rewards shortcuts: training on answers made execution collapse while the answers improved, and an answer checker would never have noticed. Learning the real procedure is hard because a shortcut that reads the answer off the surface fits the training data too, and the model takes whatever is easier to find.

For agents, much of this is already handled by harnesses, whose main job is managing context and state: deciding what the model sees at each call and keeping everything else outside it. The study gives one reason why that works. The same trained model completed 156 runs when the gym held the state, against 100 when it carried the state in its own text, and in long written runs the first error came later the longer the run, which fits losing the state. A harness that holds the state exactly and keeps errors out of the history does work the model cannot yet do reliably, although no harness can supply a step the model never learned.

For architecture, the unit that trained well was the single step, and a run is that step repeated. That is the shape of a looped transformer, which applies the same block again and again; whether looping would help here is my speculation, not something this study tested. It is also possible that much larger models learn to manage their own state well enough that all of this matters less.

The study has clear limits: one model family, mostly one training seed, 240 puzzles that are 30 structures in four letterings, and supervised training only. Still open are reinforcement learning with the step check as the reward, and what the model computes in a single pass on the puzzles it does decide.
