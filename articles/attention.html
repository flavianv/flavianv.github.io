Transformers,
focus: attention.

A transformer block in one picture, then attention from first principles: the intuition, the math and the PyTorch, line by line, followed by the variants that make it cheap enough to serve (multi-query, grouped-query and latent attention) and FlashAttention, which computes exactly the same thing, much faster.

Video coming soon on YouTube ↗ · Code and measurements: github.com/flavianv/ai_tutorials/attention/code

01 / The transformer block

Text becomes tokens, and tokens become vectors that flow up a stack of identical blocks. The vector at each position is a notepad, the residual stream, that every block reads from and adds to. Each block does two things: attention, where tokens exchange information, and an MLP, where each token processes what it heard on its own. A normalization precedes each step, and each result is added back rather than overwriting. The last vector predicts the next token.

02 / Why tokens need to talk

In “the animal didn’t cross the street because it was too tired”, the word “it” must find “animal”. Recurrent networks squeezed the past into one vector; Bahdanau, Cho and Bengio let a translator look back at every input word, and Attention Is All You Need (2017) removed recurrence entirely: every token attends to every other token, in parallel.

03 / Queries, keys, values

Attention is a soft lookup. Each token emits a query (what am I looking for?), a key (what do I contain?) and a value (what I hand over), through three learned matrices. Instead of returning one match, attention returns a blend of every value, weighted by how well each key matches the query.

04 / Scores, and why √d

A query and a key are compared by their dot product. If their components are independent with mean 0 and variance 1, the dot product is a sum of d such terms, with variance d, so large scores would make the softmax extremely peaky and its gradients tiny. Dividing by √d restores unit variance:

Var(q · k) = Σ_i Var(q_i k_i) = d ⇒ (q · k)/√d has variance 1

05 / Softmax, the weighted sum and the mask

Softmax turns each row of scores into positive weights summing to one: each token spends one unit of attention. The output is the weighted average of the values. For language models, a causal mask sets scores above the diagonal to −∞, so tokens never see the future:

Attention(Q, K, V) = softmax( QKᵀ / √d ) V  (n×d)(d×n) → n×n, (n×n)(n×d) → n×d
def attention(q, k, v, causal=False):                  # q, k, v: (..., n, d)
    d = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d)    # (..., n, n): every query vs every key
    if causal:                                         # no peeking at future tokens
        n = q.size(-2)
        mask = torch.ones(n, n, dtype=torch.bool, device=q.device).triu(1)
        scores = scores.masked_fill(mask, float("-inf"))
    weights = scores.softmax(dim=-1)                   # each row sums to 1
    return weights @ v                                 # weighted average of the values

Compared with F.scaled_dot_product_attention, with and without the mask, the largest difference was below 10⁻⁶.

06 / Multi-head attention

A single attention pattern is one way of reading the sentence. Heads run several in parallel (who does “it” refer to, what is the verb, what came just before), each in a slice of the model width: eight heads of 64 dimensions for a width of 512, at the same cost. In code, view splits the features into heads, transpose(1, 2) moves the heads in front as an extra batch dimension, and after attention the heads are glued back together and mixed by an output projection:

class MultiHeadAttention(nn.Module):                   # n_kv_heads: = n_heads MHA, = 1 MQA, else GQA
    def __init__(self, d_model, n_heads, n_kv_heads=None):
        super().__init__()
        self.h, self.kv = n_heads, n_kv_heads or n_heads
        self.dh = d_model // n_heads
        self.wq = nn.Linear(d_model, self.h * self.dh, bias=False)
        self.wk = nn.Linear(d_model, self.kv * self.dh, bias=False)
        self.wv = nn.Linear(d_model, self.kv * self.dh, bias=False)
        self.wo = nn.Linear(self.h * self.dh, d_model, bias=False)

    def forward(self, x, causal=True):
        B, n, _ = x.shape
        q = self.wq(x).view(B, n, self.h, self.dh).transpose(1, 2)     # (B, h, n, dh)
        k = self.wk(x).view(B, n, self.kv, self.dh).transpose(1, 2)    # (B, kv, n, dh)
        v = self.wv(x).view(B, n, self.kv, self.dh).transpose(1, 2)
        k = k.repeat_interleave(self.h // self.kv, dim=1)              # a group of query heads
        v = v.repeat_interleave(self.h // self.kv, dim=1)              # shares one K and V
        out = attention(q, k, v, causal)                               # (B, h, n, dh)
        return self.wo(out.transpose(1, 2).reshape(B, n, -1))          # concat heads, mix

The n_kv_heads argument gives MHA (as many key-value heads as query heads), GQA (fewer) or MQA (one); repeat_interleave lets each key-value head serve a group of query heads. The module matched PyTorch’s attention within about 2 × 10⁻⁷ for 8, 2 and 1 key-value heads.

07 / The block in code

class Block(nn.Module):                                # a pre-norm transformer block
    def __init__(self, d_model, n_heads, n_kv_heads=None):
        super().__init__()
        self.norm1, self.norm2 = nn.RMSNorm(d_model), nn.RMSNorm(d_model)
        self.attn = MultiHeadAttention(d_model, n_heads, n_kv_heads)
        self.mlp = nn.Sequential(nn.Linear(d_model, 4 * d_model), nn.GELU(),
                                 nn.Linear(4 * d_model, d_model))

    def forward(self, x):
        x = x + self.attn(self.norm1(x))               # tokens talk to each other
        x = x + self.mlp(self.norm2(x))                # each token thinks on its own
        return x

Two lines do the work, and the plus signs are the residual stream. Normalizing before each step (pre-norm) trains more stably than the original post-norm design (Xiong et al., 2020); Llama-style models use RMSNorm, SwiGLU and rotary position embeddings.

08 / The bill, and MQA, GQA, MLA

Scores are n × n per head: at 8,192 tokens and 8 heads in 32-bit floats, 2 GB per layer. Generation adds a second bill, the KV cache of past keys and values:

KV bytes / token = 2 × L × h_kv × d_h × bytes

For a Llama 3 8B-sized model (32 layers, 32 query heads of 128 dimensions, fp16), full multi-head attention would need 512 KiB per token. Multi-query attention (Shazeer, 2019) shares one key-value head: 16 KiB. Grouped-query attention (Ainslie et al., 2023) sits in between; Llama 3 8B uses 8 key-value heads, 128 KiB per token, or 1 GiB instead of 4 GiB at 8,192 tokens. The GQA paper uptrains existing multi-head checkpoints with about 5% of the original pre-training compute. DeepSeek-V2’s multi-head latent attention caches a small latent per token and reconstructs keys and values from it, reporting a 93.3% smaller KV cache than DeepSeek 67B.

09 / The zoo

Sliding-window attention looks only at recent tokens (Mistral 7B: 4,096), linear attention regroups (QKᵀ)V as Q(KᵀV) for linear cost (Katharopoulos et al., 2020), and cross-attention takes queries from one sequence and keys and values from another. Attention is also order-blind, so positions must be injected separately: that is the next episode. Lilian Weng’s Attention? Attention! and The Transformer Family Version 2.0 map this zoo in depth.

10 / FlashAttention and the online softmax

Attention is usually limited by memory traffic, not arithmetic: standard implementations write the n × n matrix to the GPU’s large, slow HBM and read it back several times. FlashAttention (Dao et al., 2022) tiles queries, keys and values into the small, fast on-chip SRAM and never materializes the full matrix. It is exact, uses memory linear in sequence length, and recomputes tiles in the backward pass; the paper reports 3× faster GPT-2 training at sequence length 1K. FlashAttention-2 is about 2× faster again, and FlashAttention-3 reaches up to 740 TFLOPs/s in FP16 on an H100.

The key is the online softmax: keep, per query, a running maximum m, a running sum ℓ and a running output o, and when a new block of scores arrives, rescale what was accumulated by e^(m − m′):

m′ = max(m, max_j s_j) ℓ′ = ℓ e^(m−m′) + Σ_j e^(s_j − m′) o′ = o e^(m−m′) + Σ_j e^(s_j − m′) v_j out = o / ℓ
def flash_attention(q, k, v, block=128):               # same result, never builds the n x n matrix
    n, d = q.shape[-2], q.shape[-1]
    out = torch.empty_like(q)
    for i in range(0, n, block):                       # one block of queries (kept in fast SRAM)
        qi = q[..., i:i + block, :] / math.sqrt(d)
        m = torch.full(qi.shape[:-1], float("-inf"), device=q.device)   # running max
        l = torch.zeros(qi.shape[:-1], device=q.device)                 # running sum
        acc = torch.zeros_like(qi)                                      # running output
        for j in range(0, n, block):                   # stream blocks of keys and values
            s = qi @ k[..., j:j + block, :].transpose(-2, -1)
            m_new = torch.maximum(m, s.amax(dim=-1))
            p = torch.exp(s - m_new[..., None])
            scale = torch.exp(m - m_new)               # rescale what we had so far
            l = l * scale + p.sum(dim=-1)
            acc = acc * scale[..., None] + p @ v[..., j:j + block, :]
            m = m_new
        out[..., i:i + block, :] = acc / l[..., None]
    return out

This plain-PyTorch version matched ordinary attention within about 4 × 10⁻⁷.

11 / In practice: one call

F.scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True) chooses a FlashAttention, memory-efficient or math backend (the sdpa_kernel context manager forces one; enable_gqa needs PyTorch 2.5+). On a MacBook’s GPU, at 8,192 tokens, it took about 153 ms per call against about 295 ms for our naive version; that is not the flash kernel, which needs a supported NVIDIA GPU.

Query, key, value, repeat.

A block is attention (tokens talk) plus an MLP (tokens think) on a residual notepad; attention is softmax(QKᵀ/√d)V with a causal mask; heads read in parallel, and MQA, GQA and MLA shrink the KV cache; FlashAttention is the same math, tiled, with an online softmax. Understand it in ten lines of PyTorch, ship it with one call.
