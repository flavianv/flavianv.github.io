REINFORCE
from scratch.

The first episode of Basics: one idea, from first principles to working code. REINFORCE sits underneath PPO, GRPO and much of reinforcement learning for language models. Here is every equation, derived, and the PyTorch that implements it, with learning curves measured from that exact code.

Watch on YouTube ↗ · Code: github.com/flavianv/ai_tutorials/reinforce/code

01 / The setup

A policy πθ(a | s) is a probability distribution over actions given a state; θ are the weights of a network. Running it in an environment produces a trajectory τ = (s0, a0, r0, s1, …, sT), whose return is the sum of rewards. The goal is to maximize the expected return:

R(τ) = Σ_t r_t  J(θ) = E_(τ∼π_θ)[ R(τ) ]

Start with a single step, a bandit: pick an action, get a reward, done.

02 / The problem

For a bandit, J is a sum over actions of probability times reward, and its gradient only touches the probabilities:

J(θ) = Σ_a π_θ(a) r(a)  ∇_θ J = Σ_a ∇_θ π_θ(a) · r(a)

That is a sum of gradients of probabilities, not an expectation, so it cannot be estimated by sampling. In real environments we cannot sum over every action or trajectory, and sampling a discrete action is not differentiable, so plain backpropagation cannot help.

03 / The log-derivative trick

By the chain rule, the gradient of log p is the gradient of p divided by p. Multiplying both sides by p gives the identity everything rests on:

∇_θ log p_θ(x) = ∇_θ p_θ(x) / p_θ(x) ⇒ ∇_θ p_θ(x) = p_θ(x) · ∇_θ log p_θ(x)

Plugging it in, the probability reappears in front of every term, and a probability-weighted sum is an expectation again: the score-function estimator, which can be estimated by sampling, without any derivative of the environment.

∇_θ J = Σ_a π_θ(a) ∇_θ log π_θ(a) r(a) = E_(a∼π_θ)[ r(a) ∇_θ log π_θ(a) ] ≈ (1/N) Σ_i r(a_i) ∇_θ log π_θ(a_i)

04 / From one step to trajectories

The probability of a trajectory is a product of the start-state probability, the policy’s choices and the environment’s transitions. Taking the log turns it into a sum, and the gradient kills every term that does not depend on θ:

p_θ(τ) = p(s_0) Π_t π_θ(a_t | s_t) P(s_(t+1) | s_t, a_t)
∇_θ log p_θ(τ) = 0 + Σ_t ∇_θ log π_θ(a_t | s_t) + 0

We never need a model of the environment: that is what makes policy gradients model-free.

05 / The REINFORCE estimator

∇_θ J ≈ (1/N) Σ_i Σ_t ∇_θ log π_θ(a_t^i | s_t^i) · R(τ^i)

Ronald Williams introduced it in 1992 (Machine Learning 8:229–256), with the acronym REward Increment = Nonnegative Factor × Offset Reinforcement × Characteristic Eligibility: a learning rate, a reward minus a baseline, and ∇ log π.

06 / Causality: reward-to-go

An action cannot change rewards collected before it. For any earlier reward, the expected product of that reward and the score of a later action is zero, because the score has zero mean given the past. Dropping those terms leaves the reward-to-go, usually with a discount γ:

E[ r_(t′) ∇_θ log π_θ(a_t | s_t) ] = 0 (t′ < t)  G_t = Σ_(t′≥t) γ^(t′−t) r_(t′)

07 / Baselines

If every return is positive, every action is pushed up. Subtracting a baseline b(s) that depends only on the state changes nothing on average, because the score has zero mean:

E_(a∼π_θ)[ ∇_θ log π_θ(a | s) b(s) ] = b(s) Σ_a ∇_θ π_θ(a | s) = b(s) ∇_θ Σ_a π_θ(a | s) = b(s) ∇_θ 1 = 0

but it can greatly reduce variance. Gt − b(st) is the advantage At: how much better the action turned out than expected. Common choices for b are the average return, a learned value function (actor-critic), or the mean of a group of samples (GRPO).

08 / What it is really doing

The objective is weighted maximum likelihood: supervised learning where the labels are the policy’s own actions and the weights are their advantages. With every advantage equal to one, it is exactly supervised fine-tuning.

max_θ Σ_t A_t log π_θ(a_t | s_t)  A_t = 1 ⇒ SFT

09 / The surrogate loss

In PyTorch we write a loss whose gradient is the REINFORCE gradient, with a minus sign because optimizers minimize, and with the advantage treated as a constant (stop-gradient):

L(θ) = − Σ_t log π_θ(a_t | s_t) · sg[A_t]  −∇_θ L(θ) = Σ_t A_t ∇_θ log π_θ(a_t | s_t)

The value of this loss is meaningless and can rise while the policy improves: watch the return, not the loss.

10 / The code

The whole algorithm on CartPole-v1, exactly as shown in the film:

import gymnasium as gym
import torch, torch.nn as nn
from torch.distributions import Categorical

env = gym.make("CartPole-v1")
policy = nn.Sequential(nn.Linear(4, 128), nn.ReLU(), nn.Linear(128, 2))
opt = torch.optim.Adam(policy.parameters(), lr=3e-3)
gamma = 0.99

for episode in range(500):
    obs, _ = env.reset(seed=episode)
    log_probs, rewards, done = [], [], False
    while not done:                                    # 1. sample a trajectory
        logits = policy(torch.as_tensor(obs, dtype=torch.float32))
        dist = Categorical(logits=logits)
        action = dist.sample()
        log_probs.append(dist.log_prob(action))        # log pi(a_t | s_t)
        obs, r, terminated, truncated, _ = env.step(action.item())
        rewards.append(r)
        done = terminated or truncated

    G, returns = 0.0, []
    for r in reversed(rewards):                        # 2. reward-to-go G_t
        G = r + gamma * G
        returns.insert(0, G)
    returns = torch.tensor(returns)                    # a constant: no gradient
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)   # baseline + scale

    loss = -(torch.stack(log_probs) * returns).sum()   # 3. surrogate loss
    opt.zero_grad()
    loss.backward()                                    # autograd = REINFORCE gradient
    opt.step()

11 / Does it work?

We ran this code with five seeds (torch 2.8.0, gymnasium 1.1.1). All five learned: from about 39 steps per episode on average over the first 50 episodes to between about 390 and 490 over the last 50, out of 500, and every seed reached 500 at least once. With the learning rate raised to 1e-2, only one seed ended near the top and one collapsed to about 9 steps and never recovered. run_curves.py in the repository reproduces both.

12 / Pitfalls

  • Forgetting the minus sign minimizes the return.
  • Letting gradients flow through the advantage optimizes a different objective.
  • Reusing old trajectories after an update breaks the on-policy assumption; reusing data needs importance ratios, which is where PPO and pessimism come in.
  • Expect high variance: normalize returns, batch episodes, and consider an entropy bonus.

13 / Where it leads

Most modern policy optimization is REINFORCE plus a fix: actor-critic learns the baseline, PPO adds a trust region, GRPO uses a group mean, RLOO a leave-one-out baseline. For language models the policy is the model, an action is a token and a trajectory is a completion. Ahmadian et al. (2024) found that REINFORCE-style variants such as RLOO outperformed PPO and “RL-free” methods such as DPO and RAFT for learning from human feedback.

Sample. Score. Weight. Step.

We want the gradient of an expectation under our own policy; the log trick turns it back into an expectation we can sample; the environment drops out and only log π remains; reward-to-go and a baseline cut variance without bias; and in code it is one surrogate loss, with autograd doing the rest.
